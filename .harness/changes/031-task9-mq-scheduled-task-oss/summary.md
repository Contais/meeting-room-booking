# MQ + 定时任务 + OSS（需求分析）

## 需求描述

基础设施能力建设：
1. **RocketMQ**：消息队列，支撑异步解耦（站内信、预约通知等）
2. **定时任务**：处理延时/周期性任务（预约提醒、状态自动流转）
3. **OSS**：对象存储，用于会议室图片、用户头像等文件存储

## 一、RocketMQ

### 1.1 现状

- 技术栈已选型 RocketMQ，`pom.xml` 已引入依赖
- 工程规范已要求消费者幂等（红线 #3）
- **但无实际业务场景接入**，MQ 尚未启用

### 1.2 可落地的业务场景

| 场景 | Producer | Consumer | 说明 |
|------|----------|----------|------|
| 站内信异步发送 | 各业务模块 | mrb-user/notification | 解耦通知发送，避免阻塞主流程 |
| 预约创建通知 | mrb-meeting | mrb-user/notification | 预约成功后异步通知参会人 |
| 审批结果通知 | mrb-user/workflow | mrb-user/notification | 审批通过/拒绝后通知发起人 |
| 预约状态变更广播 | mrb-meeting | mrb-gateway(WebSocket) | 实时刷新日历视图（可选） |

### 1.3 Topic 规划

| Topic | 用途 | Tag |
|-------|------|-----|
| `mrb-notification` | 站内信 | RESERVATION / APPROVAL / SYSTEM |
| `mrb-reservation-event` | 预约事件 | CREATED / CANCELLED / APPROVED |

### 1.4 落地建议

- **一期范围**：仅接入「站内信异步发送」一个场景，验证 MQ 链路
- 消费者必须幂等：以 `notification.id` 或业务唯一键做去重
- Key 前缀遵循红线：`mrb:mq:dedup:{topic}:{msgKey}`

### 1.5 风险

- MQ 不可用时需有降级策略（同步发送兜底）
- 消息堆积需监控
- 幂等去重 Key 需设计合理，避免误判

## 二、定时任务

### 2.1 现状

- 无定时任务框架
- 无周期性业务任务

### 2.2 可落地的业务场景

| 场景 | 触发周期 | 说明 |
|------|----------|------|
| 预约即将开始提醒 | 每分钟扫描 | 会议开始前 15/30 分钟通知 |
| 预约超时未审批自动取消 | 每 5 分钟 | 待审批预约超时（如 2 小时）自动取消 |
| 过期预约状态归档 | 每天 00:30 | 历史预约归档/统计 |
| 会议室状态巡检 | 每小时 | 检查禁用会议室是否有未来预约 |
| 站内信清理 | 每天 03:00 | 清理 90 天前已读消息 |

### 2.3 技术选型

| 方案 | 优点 | 缺点 | 建议 |
|------|------|------|------|
| Spring `@Scheduled` | 简单、零依赖 | 单机、无分布式锁 | 一期采用 |
| XXL-JOB | 分布式、可视化 | 需部署调度中心 | 二期考虑 |
| Quartz | 功能全 | 配置复杂 | 不推荐 |

**一期建议**：使用 Spring `@Scheduled` + Redis 分布式锁（`mrb:schedule:lock:{task}`），满足当前单实例部署。

### 2.4 实现要点

```java
@Scheduled(cron = "0 */1 * * * ?")  // 每分钟
public void remindUpcomingReservation() {
    // 1. 获取 Redis 锁（防多实例重复执行）
    // 2. 查询 15-30 分钟内即将开始的预约
    // 3. 发送站内信（通过 MQ）
    // 4. 释放锁
}
```

### 2.5 风险

- 定时任务需避免与正常业务冲突（锁竞争）
- 大批量数据扫描需分页，避免内存溢出
- 时区问题：`@Scheduled` 默认 JVM 时区，需确认 Asia/Shanghai

## 三、OSS 对象存储

### 3.1 现状

- 会议室图片 `image_url`、用户头像 `avatar` 均为字符串字段
- 当前无统一文件上传接口，可能为本地存储或外部 URL

### 3.2 可落地的业务场景

| 场景 | 文件类型 | 说明 |
|------|----------|------|
| 会议室图片上传 | jpg/png | 管理员新增/编辑会议室时上传 |
| 用户头像上传 | jpg/png | 个人中心修改头像 |
| 会议附件（未来） | pdf/doc | 预约关联会议材料 |

### 3.3 技术选型

| 方案 | 优点 | 缺点 | 建议 |
|------|------|------|------|
| 阿里云 OSS | 稳定、CDN 加速 | 收费 | 生产推荐 |
| MinIO（自建） | 免费、S3 兼容 | 需运维 | 开发/私有部署推荐 |
| 本地存储 | 零成本 | 不支持分布式、无 CDN | 仅开发环境 |

**建议**：抽象 `FileStorageService` 接口，一期用本地存储实现，二期切换 OSS/MinIO 无感知。

### 3.4 接口设计

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/file/upload` | POST | 文件上传，返回 URL |
| `/api/file/delete` | DELETE | 删除文件（管理员） |

上传参数：
- `file`：文件
- `bizType`：业务类型（ROOM_IMAGE / AVATAR）
- 限制：大小 5MB、类型 jpg/png/webp

### 3.5 实现要点

- 文件路径规则：`{bizType}/{yyyyMM}/{uuid}.{ext}`
- 返回 URL 供前端 `<img :src>` 使用
- 头像/会议室图片字段已存在（`avatar` / `image_url`），无需改表

### 3.6 风险

- 本地存储在容器化部署时需挂载持久卷
- 文件删除需防止误删（校验归属）
- 上传需鉴权，防止匿名上传

## 落地优先级建议

| 优先级 | 能力 | 依赖 | 建议时机 |
|--------|------|------|----------|
| P0 | 定时任务（预约提醒/超时取消） | 无 | 立即 |
| P1 | OSS/文件上传（会议室图片/头像） | 无 | 立即 |
| P2 | MQ（站内信异步） | task8 站内信 | task8 实现时同步接入 |

## 冲突与风险

- **风险1**：MQ 与定时任务均涉及通知发送，需统一通知入口避免重复
- **风险2**：定时任务分布式锁需确保 Redis 可用，否则可能重复执行
- **风险3**：OSS 方案选型影响部署架构，需与运维确认
