# 聊天机器人回复重复内容修复 — 提示词优化

## 需求摘要

用户反馈：聊天窗口 AI 回复出现内容重复，如"好的，今天是2026年7月27日，我来看看哪些会议室…"之后又出现"好的！今天是 2026年7月27日，我查了一下适合容纳10人的会议室…"，同一段意思说了两遍。

## 根因分析

两层因素叠加：

1. **技术机制**：`ChatController` 使用 `.stream().content()` 返回 `Flux<String>`，前端 `ChatPanel.vue` 用 `accumulatedContent += decoder.decode()` 累积所有流式 chunk。Spring AI 在流式 + Function Calling 场景下，模型会在调用工具**前**输出"前奏文本"、工具返回**后**再输出"总结文本"，两段意思相近，全被拼接显示即为重复。
2. **提示词问题**：原 `chatbot-system-prompt.md` 的【输出规则】大量使用负面指令 + 反面示例措辞（"让我看看…"、"好的呀让我先…"、"我来帮你查查…"、"稍等哦~"），这些带引号的示例本身会被模型模仿，且缺少正向的工具调用流程约束。

## 技术变更清单

| 文件 | 变更 |
|------|------|
| `backend/mrb-meeting/src/main/resources/prompt/chatbot-system-prompt.md` | 重写【输出规则】6 条：用正向指令替代负面指令（"工具前静默"替代"禁止引导性前奏"、"单次回复"替代"拒绝自言自语"）；删除所有反面示例措辞；新增正面输出示例（表格格式范式） |

## 冲突与风险

- 纯提示词 md 改动，无 Java / 前端 / API / DB / MQ 变更。
- 红线 #7（`<script setup>`）不受影响。
- 提示词为运行时 classpath 资源，无需编译验证；重启后端服务即生效。
- 正向指令 + 正面示例的提示工程实践比"禁止 X"更有效，但最终效果取决于模型（DeepSeek）的遵循程度，需实际对话验证。
