# 068-forgot-password-page 需求分析摘要

## 需求描述

将登录页「忘记密码」从弹窗重构为独立页面（`/forgot-password`），保留原邮箱验证码找回流程，不修改后端接口与业务逻辑。

方案要点：
- 新增独立路由页面，替代 `LoginView` 内的 `el-dialog`，登录页只保留入口链接。
- 页面采用两步流程（身份验证 → 设置新密码）并带步骤指示，替代单弹窗堆 4 个字段。
- 校验从「提交后 toast」升级为字段级内联校验（Element Plus `rules`），并补齐 `autocomplete`、自动聚焦、触控尺寸等无障碍细节。
- 视觉与登录页共享同一套设计语言（深紫渐变背景、20px 圆角卡片、渐变主按钮），避免弹窗与主页面风格割裂。

## 验收标准

- [ ] 点击登录页「忘记密码」跳转 `/forgot-password`，不再弹出对话框
- [ ] 第一步输入用户名发送验证码：已绑定邮箱返回成功提示，未绑定邮箱返回 1024 提示
- [ ] 验证码输入框带 60 秒发送冷却与 loading 状态，文案「5 分钟内有效」常驻可见
- [ ] 第二步设置新密码（6-64 位）并二次确认，字段级内联报错、提交后聚焦首个错误字段
- [ ] 重置成功后展示成功态并返回登录页，用户名自动回填
- [ ] 无障碍：用户名/密码/验证码带 `autocomplete`，页面打开自动聚焦首个输入框，错误信息关联字段
- [ ] 375px 小屏无横向滚动，输入框与按钮触控高度 ≥44px
- [ ] 前端 `npm run build` 通过

## 技术变更清单

| 变更 | 说明 |
|------|------|
| `frontend/src/views/auth/ForgotPasswordView.vue`（新增） | 独立找回密码页：两步流程 + 成功态 + 响应式 + 无障碍 |
| `frontend/src/router/index.ts` | 新增 `/forgot-password` 路由（免登录，标题「找回密码」） |
| `frontend/src/views/auth/LoginView.vue` | 移除找回密码弹窗及相关状态/定时器，入口改为路由链接，支持 query 回填用户名 |

后端接口（`/api/uc/user/forgot-password/send-code`、`/reset`）、网关白名单、Redis 逻辑均不修改。

## 业务影响范围

- 仅影响未登录用户的登录/找回入口；登录页视觉与交互无其他变化。
- 无 DB、MQ、缓存逻辑变更。

## 冲突与风险

- **用户枚举**（沿用既有设计）：发送接口对「用户不存在」与「未绑定邮箱」返回不同提示，会暴露账号是否存在；属内部系统可接受，本次不收紧，仅在前端文档中记录。
- **验证码过期**：验证码 5 分钟有效，页面以常驻 helper text 告知用户，避免误判。
- **分支规范**：本次在 `feature/068-forgot-password-page` 分支开发，按手册约定不直接提交 `main`。

## 任务拆分

1. 新增 `ForgotPasswordView` 页面（两步流程 + 校验 + 成功态 + 响应式）
2. 注册 `/forgot-password` 路由
3. 登录页移除弹窗、接入路由链接与用户名回填
4. 前端构建验证并提交
