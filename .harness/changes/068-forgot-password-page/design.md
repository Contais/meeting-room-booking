# 068-forgot-password-page 设计方案

## 背景

现有找回密码以 `el-dialog` 形式挂在登录页内，存在视觉割裂（默认 Element Plus 皮肤 vs 登录页定制风格）、四字段单弹窗认知负担高、校验靠 toast、无步骤感、移动端 420px 固定宽度有溢出风险等问题。

## 方案决策

### 独立页面而非弹窗

密码找回是登录失败的出口，属于用户主路径上的恢复流程，而非临时辅助操作。独立页面支持：

- 浏览器原生返回与深链接（邮件通知可直接指向 `/forgot-password`）
- 多步骤流程的展示空间与步骤指示
- 与登录页一致的全屏品牌背景，避免弹窗与页面风格割裂

### 两步流程

1. **身份验证**：用户名 + 邮箱验证码（发送按钮带 60s 冷却与 loading）
2. **设置新密码**：新密码 + 确认密码（6-64 位，与后端 DTO 校验一致）

成功后展示成功态页面，点击「返回登录」跳转登录页并回填用户名。

## 页面结构

```
ForgotPasswordView
├── 背景层：深紫渐变 + 浮动圆形（与 LoginView 一致）
├── 卡片（460px，圆角 20px）
│   ├── 品牌标记 + 标题「找回密码」+ 副标题
│   ├── 步骤指示器（验证身份 → 设置新密码）
│   ├── 第一步表单（用户名 / 验证码+发送按钮 / helper text）
│   ├── 第二步表单（新密码 / 确认密码 / 上一步+确认重置）
│   ├── 成功态（对勾 + 返回登录按钮）
│   └── 底部「已有账号？返回登录」链接
└── ICP 页脚（与登录页一致）
```

## 校验与无障碍

- 使用 Element Plus `rules` 内联校验：用户名必填、验证码 6 位数字、新密码 6-64 位、确认密码一致；blur 触发。
- `autocomplete`：`username` / `one-time-code` / `new-password`，兼容密码管理器。
- 页面挂载自动聚焦用户名；进入第二步自动聚焦新密码。
- 错误信息由 `el-form-item` 内联渲染并关联字段，提交失败时 Element Plus 自动滚动聚焦首个错误字段。

## 视觉规范（与登录页对齐）

| 元素 | 取值 |
|------|------|
| 背景 | `linear-gradient(135deg, #0f0c29, #302b63, #24243e)` + 浮动圆形 |
| 卡片 | 白底、圆角 20px、`box-shadow 0 25px 60px rgba(0,0,0,.4)` |
| 输入框 | 圆角 10px、1px `#e0e0e0` 描边、聚焦 2px `#667eea` |
| 主按钮 | 渐变 `#667eea → #764ba2`、48px 高、hover 上浮 + 阴影 |
| 步骤指示器 | 28px 圆形节点，激活态渐变填充，完成态对勾 |
| 成功态 | 语义绿对勾 + 标题 + 引导文案 |

## 动效与响应式

- 步骤切换使用 `transition`（opacity + translateY，0.25s，out-in），仅 transform/opacity，不触发重排。
- `@media (max-width: 480px)`：卡片宽度 `calc(100% - 32px)`、内边距收窄、标题降级。
- `@media (prefers-reduced-motion: reduce)`：关闭背景浮动动画。

## 不做的事

- 不修改后端接口、错误码、Redis 逻辑与网关白名单。
- 不收紧「用户不存在 / 未绑定邮箱」的用户枚举提示（维持现状，风险已记录）。
